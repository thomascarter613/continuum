APCMS is being planned as a **standalone product/system**, not a documentation template and not an extension of Monad.

The goal will be to create something that can sit *underneath virtually any AI-assisted software project*:

```text
                    HUMAN
                      │
                      ▼
             ┌─────────────────┐
             │   AI Assistant  │
             │ Claude / GPT /  │
             │ Gemini / Codex  │
             │ Local models... │
             └────────┬────────┘
                      │
                      ▼
       ┌──────────────────────────────┐
       │      PROJECT MEMORY SYSTEM   │
       │                              │
       │  Intent                      │
       │  Requirements                │
       │  Constraints                 │
       │  Architecture                │
       │  Decisions                   │
       │  Domain                      │
       │  Artifacts                   │
       │  State                       │
       │  Work                        │
       │  History                     │
       │  Questions                   │
       │  Evidence                    │
       │  Traceability                │
       └──────────────┬───────────────┘
                      │
                      ▼
                 PROJECT REPO
```

And eventually:

```text
AI #1 ──┐
AI #2 ──┤
AI #3 ──┼──► Project Memory ──► Software Project
AI #4 ──┤
Human ──┘
```

The important thing is that **the project becomes persistent while AI sessions become disposable**.

# First objective

Before we write code, we will establish the **system itself**.

## Phase 0 — Define the system

Establish:

1. Name
2. Purpose
3. Problem statement
4. Design principles
5. Scope
6. Non-goals
7. Users
8. Core concepts
9. Operating model
10. Success criteria

## Phase 1 — Create the conceptual model

Define the ontology:

```text
Project
 ├── Intent
 ├── Goal
 ├── Requirement
 ├── Constraint
 ├── Decision
 ├── Question
 ├── Hypothesis
 ├── Proposal
 ├── Domain Concept
 ├── Artifact
 ├── Architecture
 ├── Work
 ├── State
 ├── Event
 ├── Evidence
 └── Relationship
```

This is the foundation.

## Phase 2 — Design the memory model

Determine:

* authoritative memory
* derived memory
* transient context
* provenance
* versioning
* temporal state
* conflicts
* supersession
* uncertainty
* confidence
* human approval
* AI-generated knowledge
* source/evidence tracking

## Phase 3 — Design the Context Engine

For example, given:

```text
Task:
"Implement document persistence"
```

the system should automatically determine that the AI probably needs:

```text
Relevant requirements
Relevant constraints
Relevant architecture
Relevant domain concepts
Relevant ADRs
Relevant source files
Relevant tests
Current work packet
Known issues
Recent history
Open questions
```

rather than dumping the entire project into context.

## Phase 4 — Design the interaction protocol

Define how humans and AI interact with it.

For example:

```text
INIT
LOAD
PLAN
PROPOSE
ASK
DECIDE
IMPLEMENT
RECORD
CHECKPOINT
SYNC
RECONCILE
HANDOFF
```

## Phase 5 — Design the filesystem format

The first implementation should be **local-first and repository-native**.

Something approximately like:

```text
project/
│
├── .memory/
│   ├── project.yaml
│   ├── intent/
│   ├── requirements/
│   ├── constraints/
│   ├── decisions/
│   ├── domain/
│   ├── architecture/
│   ├── artifacts/
│   ├── work/
│   ├── questions/
│   ├── evidence/
│   ├── history/
│   └── state/
│
├── src/
├── tests/
└── ...
```

## Phase 6 — Build the first CLI

Eventually we want something like:

```bash
pm init
pm status
pm context
pm context --task "implement document persistence"
pm decision create
pm requirement create
pm question create
pm work start
pm checkpoint
pm handoff
pm reconcile
pm verify
```

I'm using `pm` only as a placeholder; **we'll choose the actual name later**.

# one rule

**We will not start by building the CLI.** 

Instead, we're going to use a process very similar to the one we've used for Monad:

```text
Problem
   ↓
Principles
   ↓
Ontology
   ↓
Model
   ↓
Architecture
   ↓
Specification
   ↓
Implementation
   ↓
Validation
```

while maintaining the conceptual integrity of the system as we go.

---

I originally proposed calling it a **Project Memory System**.

That's useful descriptively, but I think the actual system is bigger.

It isn't merely memory.

It needs to answer:

> **What does the AI need to know right now in order to safely and correctly act on this project?**

That includes memory, but also:

* retrieval
* context construction
* state
* provenance
* reasoning boundaries
* task awareness
* authority
* change management
* reconciliation

So we will provisionally define the system as:

# AI Project Context & Memory System

**Working abbreviation:** APCMS

# Our first task

**Don't write the charter yet.**

Establish the most fundamental design decision first:

### The system should be designed around a particular philosophy:

> **The AI does not own the project's understanding. The project owns its understanding, and AI agents are temporary reasoning participants operating against it.**

We begin constructing the actual specification systematically.
